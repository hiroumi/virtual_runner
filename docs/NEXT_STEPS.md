## 現在のチューニング値（2026-09-02時点、game.py）

パラメータは複数回のフィードバックで変遷しているので、変更する際は必ず`docs/PHASE2_RACE_LOG.md`で経緯を確認してから触ること（特に「なぜその値なのか」の理由）。

- `MAX_SPEED = 90.0`（ワールド単位/秒）。HUDの速度表示はこれと独立: `HUD_MAX_DISPLAY_SPEED = 320.0`を使い、`speed / MAX_SPEED * HUD_MAX_DISPLAY_SPEED`で計算。**最高速度をさらに上げても、表示上の最大値は320のまま変えなくてよい設計。**
- `ACCEL=49.5` `BRAKE=139.5` `FRICTION=23.6` `OFFROAD_FRICTION=90.0` `OFFROAD_MAX_SPEED=40.0` `TRAFFIC_SPEED=28.0` — いずれも`MAX_SPEED`と同じ比率でスケールしてきた値。`MAX_SPEED`を変えるときはこれらも同じ比率で変えること。
- `CENTRIFUGAL=0.8` `STEER_RATE=2.0` — `speed_frac`（0〜1正規化）ベースなので、`MAX_SPEED`を変えても基本的に変更不要（安全マージンはむしろ速度が上がるほど良くなる、という逆説的な性質があるため。理由は`docs/PHASE2_RACE_LOG.md`の該当セクション参照）。
- `road.py`の`TRACK_EVENTS`: 各カーブは「長さ×ピーク曲率」の積がだいたい一定になるよう設計されている（＝安全マージン一定の設計原則）。カーブを緩くしたいときは「長さを増やしてピークを減らす」、逆に鋭くしたいときはその逆、という調整方法が確立している。
- `config.json`の`parallax_scale=1.3`、`fullscreen=false`は、ユーザーが実機で調整した値（Claude Codeが書いたものではない）。**この値は必ず維持し、根拠なく上書きしないこと。**

## 作業上の重要な注意点

1. **`config.json`はユーザーの実機テストで書き換わることがある。** ローカルパス（`/mnt/c/Users/hirou/Documents/VirtualBoyRacing/config.json`）はWindows側とWSL側で同じファイルを見ているため、ユーザーが実機でキャリブレーターやゲームを実行してSキーで保存すると、このファイルが「生きたデータ」として変化する。作業前に必ず`git diff`で現在の値を確認し、意図しない差分があれば**それを実機テストの結果として尊重し、`git checkout`等で元に戻さないこと**（過去に一度誤って元に戻しかけ、直後に復元した経緯があるので注意）。
2. **原因と対応は毎回GitHubにアップロードする。** ユーザーからの明示的な指示（2026-09-02）: 各修正について、原因と対応を`docs/PHASE2_RACE_LOG.md`（日本語、詳細）と`README.md`（英語、ユーザー向け要約）の両方に書き、コードの修正と同じコミットでpushする。
3. **実機がないと確認できないことは、はっきりそう伝える。** このセッションはWindows実機を直接操作できないため、確認は常に「WSL上でSDLダミードライバを使ったヘッドレスレンダリング＋pytest」止まり。見た目や操作感の最終確認は必ずユーザーに実機でお願いする。
4. **テストを飼い慣らす。** `road.py`のカーブや`game.py`の速度定数を変えると、`tests/test_road.py`の所要時間チェックや横方向の範囲チェックが引っかかることがある。これはバグではなく閾値が古いだけのことが多いので、実際の値を確認した上で、閾値側を意図に合わせて更新する（テストを削除するのではなく、意味のある閾値に直す）。
